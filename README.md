# 🫒 올리브영 가격 비교 (OliveYoung Price Tracker)

올리브영 베스트 상품의 가격을 매일 수집해 **시계열로 추적**하고, 세일가·정가·역대 최고/최저가를 비교하는 개인 프로젝트.

**🔗 https://ellajang.github.io/price-comparison/**

---

## 왜 만들었나

올리브영이 **"대대적 세일"** 을 할 때, 실제로는 **평소보다 가격을 올려놓고 할인처럼 보이게** 하는 경우가 있다. ("정가 부풀리기 → 할인율 뻥튀기")

이걸 눈으로 확인하려면 **세일 전후 가격을 직접 기록해두고 비교**하는 수밖에 없다. 그래서 가격을 매일 스냅샷으로 쌓아두고,

- **역대 최고가 대비** 지금이 정말 싼지 (▼내림 / ▲오름)
- **역대 최저가** 는 언제 얼마였는지
- **세일 기간에 찍힌 가격이 오히려 최고가**인지 (= 부풀리기 의심)

를 한눈에 검증하는 것이 목적이다.

---

## 왜 이런 구조인가 (핵심)

> **올리브영은 공식 가격 API를 제공하지 않고, 앞단을 Cloudflare 봇 차단으로 막아둔다.**

그래서 가격을 가져오는 방법이 제한된다:

| 방법 | 가능? | 이유 |
|------|:---:|------|
| 공식 가격 API 연동 | ❌ | 제공 안 함 |
| 브라우저(배포 사이트)에서 직접 `fetch` | ❌ | **CORS** + **Cloudflare 봇 챌린지**에 막힘 |
| **진짜 브라우저(Playwright)로 직접 방문** | ✅ | 사람처럼 접속 → 챌린지 통과 → DOM에서 가격 추출 |

핵심 제약은 **"수집은 진짜 브라우저를 띄우는 프로그램만 할 수 있다"** 는 것. 이건 정적 웹(방문자 브라우저)에선 불가능하고, **로컬(또는 서버)의 Playwright** 로만 된다.

그래서 아래 구조를 택했다:

```
[수집] 은 로컬에서 (Playwright, 주거용 IP → Cloudflare 통과)
   ↓ 결과를 SQLite에 저장
[가공] data.db → 정적 JSON(products.json)으로 구움
   ↓ git push
[배포] GitHub Actions가 정적 사이트만 빌드·배포 (수집 안 함)
   ↓
[열람] 방문자는 정적 JSON만 읽음 (올리브영에 접속하지 않음)
```

- **방문자는 올리브영을 건드리지 않는다** → 방문자 수와 무관, 서버 부담 0
- **수집은 내 PC에서 내가 돌릴 때만** 일어난다 (하루 1회)
- **비용 0** (GitHub Pages 정적 호스팅 + 로컬 수집)


## 데이터 모델

**SQLite** (`data.db`), 두 개의 테이블:

- **`products`** — 상품 1행 (goods_no, 브랜드, 이름, 이미지, URL, **역대 최저가+날짜**, 관심여부)
- **`price_snapshots`** — 가격 변동 시계열 (goods_no, 날짜, 정가, 판매가, 세일기간여부, 카테고리)

### store-on-change — 용량 폭증 방지

매일 ~2,000개를 긁지만, **가격이 바뀐 상품만** 스냅샷을 추가한다. 안 바뀐 건 저장하지 않는다.

> 실제로 **18일 수집 = 최대 36,000행이 될 것을 11,672행**으로 (약 1/3) 유지 중.

가격 곡선(추이)은 **변동 지점만** 있어도 그대로 그려지므로 정보 손실은 없다. 역대 최저가는 별도 컬럼에 **영구 박제**되어, 오래된 스냅샷을 지워도 보존된다.

## 주요 기능

- **역대 최고가 대비 게이지** — 현재가가 최고가보다 ▼내렸는지 ▲올랐는지 + hover 시 `최고 X원 (날짜)`
- **세일 부풀리기 감지** — 최고가가 **세일 기간(⚠️)** 에 찍혔으면 표시 / 낙폭이 비정상적으로 크면 **옵션(기획↔단품) 변동 가능성(?)** 표식
- **역대 최저가 + 🔥 뱃지** — 현재가가 역대 최저에 닿으면 강조
- **관심 상품(찜, ❤️)** — 베스트 순위에서 밀려나도 **상세 페이지로 직접 추적** (순위 밖 가격 갱신)
- **카테고리 필터 · 검색 · 정렬(할인율/가격) · 페이지네이션**

## 실행 방법

```bash
# 1. 데이터 수집 (로컬, 올리브영 크롤링)
npm run scrape        # 크롤링만
npm run snapshot      # 크롤링 + 정적 JSON 생성

# 2. 로컬에서 미리보기
npm run view          # http://localhost:3000 (라이브 API + 화면)
npm run web:dev       # Vite 개발 서버 (HMR)

# 3. 배포 (새 데이터 반영)
git add -A && git commit -m "chore: 가격 갱신" && git push
#   → GitHub Actions가 빌드·배포 (수집은 안 함)

# 관심 상품 관리
node watch.js list
node watch.js add <goodsNo|상품명>
node watch.js remove <goodsNo>
```

## 한계 · 참고

- **수집은 로컬에서만** — GitHub Actions 같은 데이터센터 IP는 Cloudflare에 더 잘 막혀서, 수집은 주거용 IP(내 PC)에서 수행한다.
- **실시간 아님** — 배포된 가격은 마지막으로 수집·푸시한 시점의 스냅샷이다.
- **개인 학습·비상업 용도** — 데이터 출처: 올리브영. 상업적 이용/대량 수집은 하지 않는다.
